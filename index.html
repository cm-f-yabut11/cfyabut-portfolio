KainSaan

A restaurant finder for Angeles City and Clark, backed by MongoDB.

My role
Project lead
Team
Three of us: John Paul David, Emilson Lio Madla, and me
Context
6ADDBASE, Advanced Database using MongoDB, October 2026
Built with
MongoDB Atlas, Node.js, Express, HTML, CSS, JavaScript
Links
Live site GitHub

The name plays on “Saan tayo kakain?”, Filipino for “where should we eat?” KainSaan lists 30 restaurants around Angeles City and Clark. Visitors can search by name, filter by cuisine, or press a map pin and let the site pick for them. Behind it is a MongoDB database that we designed, validated, and connected to a Node and Express server.

What it does

  • The home page has a search bar, a “Surprise me” pin that picks a restaurant at random, a top rated list, a recently added list, and cuisine tags.
  • The restaurants page has search by name, a cuisine filter, sorting, and page navigation. There are also cuisines and about pages, and a light and dark theme.
  • A separate admin page covers the full CRUD cycle: add, view, edit, and delete restaurants.
  • Deleting moves a restaurant to a trash collection first. From there it can be restored, deleted permanently, or left to expire automatically after 30 days.

The database

  • One database, dbRestaurants, with a restaurants collection and a trash collection for deleted records.
  • Each restaurant stores an ID, name, cuisine, address, rating, and contact number. New records also get a created date, which powers the “recently added” list.
  • Schema validation requires all six fields and keeps ratings between 0 and 5.
  • A unique index on the restaurant ID, indexes on name and cuisine, and a time-to-live index that clears the trash after 30 days.

Problems we ran into

  • The connection failed at first because we had used a placeholder cluster address instead of the real Atlas host.
  • We kept the database password out of the code and out of GitHub by moving it into an environment file, and moved the connection code into its own module.
  • The site first ran in a preview mode that only used browser storage, so we added Express routes to connect it to the real database.
  • File names with mixed capital letters broke on the Linux server, so we renamed everything to lowercase.
  • Restoring a deleted restaurant could reuse an ID that a new one had taken, so Restore now assigns the next free ID.

What I’d improve

The admin page has no login yet, so anyone who knows its address can open it. I left its link off this site on purpose. Next I’d add a login, move search and pagination to the server, add photos and opening hours, and keep an activity log of changes.
